# Take-Home Assignment

## Objective

Create a single HTML file that recreates the observed cube animation as accurately as possible.

Optimize for:
- Visual fidelity
- Animation/motion fidelity
- Geometry and proportions

## Hard Constraints

- Use only this coding-agent session for the implementation.
- Do not browse the internet.
- Do not visit idler.ai or any related website.
- Do not search for, inspect, or reproduce the reference implementation or its source code.
- Do not use external images, videos, screenshots, or other media as references.
- Do not use the reference media as an input to the implementation.
- The implementation must ultimately be contained in a single HTML file.
- The implementation must be completed within the strict 2-hour limit.

## Workflow

Before making major changes:

1. Briefly state the implementation approach.
2. Inspect the existing project and current implementation.
3. Make the smallest change necessary for the current task.
4. Run the project locally.
5. Verify that it renders correctly.
6. Check for runtime/build errors.
7. Fix problems before moving on.

Work incrementally rather than attempting the entire implementation at once.

When I provide visual feedback, treat that feedback as the source of truth and adjust the implementation accordingly.

## Priorities

1. Visual similarity
2. Animation/motion similarity
3. Correct geometry and proportions
4. Smooth performance
5. Single-file export
6. Code cleanliness

Do not spend significant time on unnecessary architecture, abstractions, UI, documentation, or features that do not improve the final visual result.

## Technical Approach

Prefer a simple browser-based implementation.

Use the existing project setup if appropriate.

If the project is empty, choose the simplest practical 3D/WebGL approach that can produce the required visual fidelity.

Keep dependencies minimal.

The final implementation must be self-contained in one HTML file.

## Time Management

There is a hard 2-hour implementation limit.

Continuously prioritize the highest-impact visual improvements.

If a feature is difficult or time-consuming, prefer a visually convincing approximation over a technically perfect implementation.

Do not restart or rewrite working portions without a clear visual benefit.

## Verification

Do not assume the implementation is correct because the code compiles.

Actually run the application after meaningful changes.

Verify that:

- The scene renders correctly.
- The animation runs correctly.
- There are no obvious runtime errors.
- The final HTML works independently.
- The most recently requested visual behavior is actually visible.

Do not proceed to unrelated features when the current feature is visibly broken.
